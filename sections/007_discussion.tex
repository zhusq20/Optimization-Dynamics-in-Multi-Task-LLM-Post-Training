\section{Limitations and Conclusion}
\label{sec:conclusion}
% ============================================================================

GPAS uses a local view of training. The current AdamW scaling, task gradients,
and task times can change as the student learns. Bounded-age probes expose the
cost of refreshing these measurements. Frozen banks at three checkpoints show
whether the allocation score remains predictive during training.

The simple allocation objective prices first-order inclusion probabilities.
An exact-$K$ task set also depends on pairwise task inclusion and gradient
alignment. Four-task enumeration lets us measure this term directly. The
water-filled probabilities serve as a compact allocation rule, while the
held-out exact-set error supplies the empirical check.

Taskwise AdamW creates a proposal-independent local second-moment target. It is
a different optimizer-state update from conventional AdamW and can change the
effective step size. The endpoint baselines and capability evaluations measure
that practical difference.

Cost-GPAS uses recent critical-path measurements and the current resident
teacher. Transfer contention and cache state can still create prediction error.
End-to-end GPU hours and teacher traces decide the systems result. The additive
time model serves as the online allocation score.

The central MOPD design principle is simple: state the teacher-loss objective,
keep its weights fixed during method comparison, measure gradients in the
optimizer's local geometry, and charge every response and teacher switch. GPAS
implements this principle for a chosen task width. Cost-GPAS adds measured
serving time. The $K=1,2,4$ study determines when local estimator gains translate
into faster MOPD training.
