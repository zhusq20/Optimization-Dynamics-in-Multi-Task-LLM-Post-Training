\section{Toward a Stable Multi-Task OPD Recipe}
\label{sec:recipe}

The three studies motivate a recipe organized around supervision allocation, teacher-conditioned updates, and the cost and capability profile of vocabulary feedback. Start from teachers that provide useful feedback on the student's trajectories, with consistent prompting and generation conventions. Specify the desired balance of domain capabilities and the available training budget before choosing the averaging rule and supervision method.

Choose loss averaging from the target domain weights and the observed response-length distribution (Section~\ref{sec:normalization}). GT suits an objective that weights valid tokens equally and accepts the resulting domain shares. When those shares depart from the intended allocation, DT and DR make domain weights explicit. Large cross-domain length disparities, such as those in Open-MOPD \citep{gao2026openmopddiagnosingfixingcapability}, make this correction especially relevant. Within each domain, DT retains token weighting, while DR gives equal weight to each response's mean loss. Use the length--gradient relationship in Equation~\ref{eq:weighting} to assess this choice. Record prompt quotas separately from loss weights, and track generated lengths and truncation as the student evolves.

Assess teacher interactions at a common student and optimizer state (Section~\ref{sec:subnetworks}). Examine update overlap together with direction and magnitude, retaining the optimizer history that shapes the actual step. For a domain that repeatedly loses capability, apply teacher-conditioned steps to copies of this state and measure their effects on fixed per-domain probe losses. Include a zero-current-gradient step to distinguish the contribution of current teacher feedback from optimizer history. Use reproducible cross-domain harm to guide targeted gradient or parameter interventions, then evaluate the resulting capability trajectories.

Select vocabulary feedback by comparing its resource cost and multi-domain capability profile (Section~\ref{sec:density}). Keep sampled-token supervision as a reference, and compare top-$k$ support sizes with candidate selection and normalization held fixed. Measure peak memory during student training and teacher scoring, together with end-to-end training time. Monitor retained probability mass by domain and response position to interpret coverage. Choose a lower-cost configuration when broader feedback offers no meaningful gain against the prespecified capability targets. This comparison connects the memory and runtime cost of supervision to the capabilities integrated into the shared student.

Use domain retention to select the final checkpoint. Let $s_d(\theta)$ be a development-set score for domain $d$, oriented so that higher is better, and let $\epsilon_d\geq0$ be a prespecified tolerance relative to the initial student. Select checkpoints subject to
\begin{equation}
s_d(\theta)\geq s_d(\theta_0)-\epsilon_d
\qquad\text{for every domain }d.
\label{eq:retention}
\end{equation}
Among eligible checkpoints, choose the one with the highest prespecified aggregate utility, retaining the initial student if none improves it. Assess uncertainty using paired development-score differences and evaluate the selected checkpoint on a separate test set. Report maximum per-domain regression along training and variability across independent runs alongside the selected model's capability scores.


\paragraph{Completed selection and independent testing.}
We apply endpoint, maximum-development-utility, and retention-constrained selection to ten seed-42 trajectories, with the domain tolerances fixed at two percentage points and equal utility weights before the new test results. Retention and unconstrained maximum utility select the same checkpoint on all ten trajectories: update 500 in nine cases and update 250 for PG--DT/Adam. In the latter case, the selected checkpoint scores 43.14\% on the independent four-domain test, versus 43.51\% at update 500. These results do not demonstrate an additional benefit from the retention constraint. The development benchmarks had been observed previously, so selection is exploratory; the independent test uses separately frozen questions from different sources. Appendix~\ref{app:completed_results} reports all test scores, the actual selections, and the remaining limits of matched-cost and functional validation.
