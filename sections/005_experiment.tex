\section{Experiments}
\label{sec:experiments}
% ============================================================================

The experiments separate calculation checks from the large-model efficiency
test. The controlled study verifies the estimator and optimizer-state formulas.
The four-teacher study asks whether those local gains improve MOPD training per
response and per GPU hour.

\subsection{Controlled checks}
\label{sec:controlled}

We first use three Gaussian task gradients in three coordinates. A fixed
diagonal map changes the task ranking seen by AdamW. Each method uses the same
target weights and averages 16 corrected task draws. We run 20,000 trials with
a fixed seed. Black crosses in Figure~\ref{fig:controlled_checks} show the
calculated values.

GPAS obtains an AdamW-scaled estimator error of $0.717$ relative to Uniform,
while raw gradient-norm sampling obtains $6.868$. Cost-GPAS obtains a
time-weighted error of $0.889$. The empirical values differ from the calculated
values by less than $0.5\%$ for GPAS and Cost-GPAS. A separate experiment uses
one million task draws to test Equation~\ref{eq:consistent_second_moment_target}.
The relative second-moment error is $0.816$ for conventional AdamW and $0.00235$
for taskwise AdamW. These checks support the implementation and the local
predictions used by GPAS.

\subsection{Four-teacher setup}
\label{sec:exp_setup}

The student starts from a fixed Qwen3-1.7B revision \citep{qwen2025qwen3}.
Four fixed specialists provide mathematics, code, instruction-following, and
science feedback. The run manifest records the exact model and tokenizer
revisions, precision, sharding, data versions, prompt templates, hardware, and
software. The teacher set and student initialization remain fixed for every
method.

One task unit contains 16 prompts and four independently sampled responses per
prompt, for 64 attempted responses. Reverse KL is averaged over valid tokens in
each response, over the four responses for a prompt, and then over prompts. The
response cap is 8,192 tokens. Every attempted response enters the response and
resource totals. The main objective is
\begin{equation}
    F_{\rm rel}(\theta)=\frac{1}{M}\sum_i
    \frac{\ell_i(\theta)}{\ell_i(0)}.
    \label{eq:relative_teacher_loss}
\end{equation}
The initial denominators and evaluation prompts are frozen before method
comparisons.

Every run starts from a shared round-robin warm-start checkpoint. Each task
contributes two complete task units to that checkpoint. The all-in budget is
128,000 attempted responses, including probes. Learning-rate scheduling uses
attempted responses as its clock. A $K$-task update uses $\beta_1^K$ and
$\beta_2^K$ when $\beta_1$ and $\beta_2$ denote one-task-unit AdamW decay. The
appendix specifies the matching weight-decay conversion and resume test.

\subsection{One teacher slot and complete cost accounting}
\label{sec:teacher_system}

$K$ counts task units combined before one optimizer update. Teacher residency
is a separate system choice. Every configuration uses the same GPU type, GPU
count, and one resident teacher slot. A $K=4$ update visits four teachers in a
fixed order and accumulates their gradients at one student state. The resident
teacher is served first when it belongs to the selected set. The final teacher
stays resident for the next update.

Transfers may overlap student rollout or backward. Each task unit records
teacher load and offload times, teacher-ready time, rollout, scoring, backward,
optimizer time, peak HBM, response count, and token count. Transfer tail is
$\max(0,t_{\rm ready}-t_{\rm rollout\ end})$. GPU hours equal wall time times
the number of reserved GPUs, including transfer and waiting periods. These
traces test whether reduced estimator error repays teacher-switch and probe
costs.

\subsection{Outcomes and uncertainty}
\label{sec:exp_outcomes}

The two primary plots show mean relative teacher loss against cumulative
attempted responses and GPU hours. The main table reports final mean and
task-level relative loss, responses and GPU hours to a common loss threshold,
peak HBM, responses and tokens per GPU hour, switch rate, transfer tail, and
update-time quantiles. A warm, middle, and late checkpoint from the Uniform
trajectory each supply eight frozen task units per task for the mechanism tests
in Table~\ref{tab:theory_tests}.

Held-out loss intervals use paired prompt bootstrap with fixed evaluation
generation seeds. Training plots show each configuration under the matched
prompt streams. Capability evaluation reports MATH-500 greedy pass@1, a frozen
LiveCodeBench pass@1 slice, IFBench strict accuracy, and GPQA-Diamond average@4
alongside the teacher-loss efficiency results.

The online study fixes $A_{\max}=50$ processed task units. Logs report score
age, probe count, probe GPU hours, final bounded inclusion probabilities, and
importance multipliers. The EMA decay, inclusion floor, failure penalty, and
common loss threshold are frozen in the run manifest before training results
are viewed.
