\section{Experimental Protocol and Capability Results}
\label{app:setup}

The experiments compare averaging rules, teacher-conditioned updates, and vocabulary supervision using a shared student initialization and four domain teachers. The ten joint-training configurations in Table~\ref{tab:completed_endpoints} include the original PG-DR and I64-DR/DT/GT branches. Mathematics-only PG/I64 runs provide the single-teacher comparison. All checkpoint axes count optimizer updates, and each trajectory comparison uses checkpoints completed for every included branch.

\subsection{Model, data, and training protocol}

The student is Qwen3-1.7B \citep{qwen2025qwen3}. The four frozen teachers are mathematics, code, instruction-following, and science RL descendants of the same initial model. Student and teachers share the tokenizer and native chat template with thinking disabled. The frozen protocol records model revisions and weight identities.

AdamW configurations use learning rate $2.5\times10^{-7}$ with $(\beta_1,\beta_2)=(0.9,0.98)$, $\epsilon=10^{-8}$, no weight decay or schedule, and global norm-1 clipping. Training sampling uses temperature 1 and top-$p=1$, with a 2,048-token prompt cap and 4,096-token response cap. One fresh response is sampled per prompt. Training uses seeds 42--44 for the I64 GT/DT/DR normalization capability summaries and seed 42 for the other comparisons. Each optimizer update aggregates 64 responses across all domain blocks.

The multi-teacher configurations allocate 16 prompts to each domain per update and use target domain weights $1/4$. Single-teacher configurations allocate all 64 prompts to mathematics. Prompts follow a seeded shuffled schedule, repeated after exhaustion. I64 uses the top-$k$ intersection objective in Equation~\ref{eq:topk} with $k=64$ from initialization; I16 uses $k=16$. The supplementary PG/SGD branches use a learning rate of $0.0025$ and each complete 500 updates. Hardware and deployment differ from the AdamW runs, so the capability comparison does not establish a runtime ranking.

Training prompts come from the \href{https://huggingface.co/datasets/nvidia/Nemotron-3-Nano-RL-Training-Blend}{Nemotron-3-Nano-RL-Training-Blend}: the DAPO and Skywork mathematics subsets, competition coding with unit tests, instruction following, and STEM multiple-choice questions. The frozen derived \href{https://huggingface.co/datasets/zsqzz/mopd-gpas-64k-data/tree/e3ead6f98b7089e0def39516cd06cf711b10b1ec}{four-domain release} contains the processed prompts and scoring metadata. A seeded shuffle reserves separate 64-record diagnostic and held-out splits per domain; the remaining training splits contain 21,928 mathematics, 19,041 code, 16,447 instruction-following, and 19,542 science records.

\subsection{Evaluation and scoring}

Each capability suite contains MATH-500 (500 questions from the MATH benchmark \citep{hendrycks2021math}; \href{https://huggingface.co/datasets/HuggingFaceH4/MATH-500}{dataset release}), a fixed 128-question LiveCodeBench v6 subset \citep{jain2024livecodebench}, IFBench strict (300 questions) \citep{pyatkin2025ifbench}, and GPQA Diamond (198 questions) \citep{rein2023gpqa}. Mathematics, code, and instruction following use one greedy response per question. GPQA uses four responses per question at temperature 1 and top-$p=1$. Its score is the mean correctness over all four responses, then over questions: average@4 accuracy. Evaluation permits up to 32,768 response tokens, bounded by the remaining configured 32,768-token context. Each complete suite contains 1,720 responses.

The expanded development grid comprises updates 50/100/250/500 for seven Adam trajectories and 100/250/500 for three SGD trajectories, plus the shared initial evaluation. Appendix~\ref{app:independent_domain_test} describes a separate additional-domain test. \subsection{Paired comparisons and evidence provenance}

Figure~\ref{fig:normalization_ci} shows percentile 95\% intervals. These are nominal, unadjusted intervals over evaluation questions, conditional on the trained checkpoints. Training-seed variation is a separate source of uncertainty. The same procedure supplies the initial-to-checkpoint comparisons in the evidence bundle.
