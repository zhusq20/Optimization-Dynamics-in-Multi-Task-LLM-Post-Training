\section{Experiments}
\label{sec:experiments}
% ============================================================================

The controlled experiment checks the GPAS and Cost-GPAS calculations. Frozen
gradient banks test response normalization, proposal quality, and the AdamW
score. Paired MOPD runs measure end-to-end efficiency. A final experiment
applies the task sampler to GRPO.

\paragraph{Evidence status.}
The controlled experiment is complete and reproducible from the released
script. The four-teacher MOPD and GRPO runs require a multi-GPU training setup
and remain pending in this draft. The protocol below assigns a measurement and
a success rule to each planned large-model claim.

\subsection{Controlled validation of the sampling rule}
\label{sec:controlled_experiment}

We construct three Gaussian task-gradient distributions with different raw
gradient scales, AdamW coordinate scales, and task costs. All methods target
$\lambda_i=1/3$ and apply the correction in
Equation~\ref{eq:importance_estimator}. We draw 20,000 Monte Carlo trials, with
16 corrected task gradients per trial.
The controlled comparison omits the probability floor so its proposals match
the closed-form calculation.

Figure~\ref{fig:controlled_sampling} reports three results. The calculated GPAS
error ratio is $0.698$, and the Monte Carlo ratio is $0.697$, relative to
uniform sampling. The raw-gradient proposal reaches $7.178$ times the observed
uniform error because its largest raw coordinates receive a small AdamW scale.
Cost-GPAS reaches $0.893$ times the uniform time-weighted second-moment proxy.
Every corrected proposal has a relative mean-gradient error below $2.1\%$. The
controlled experiment checks the estimator and implementation. The LLM study
tests score quality, teacher compatibility, and training progress.

\subsection{Four-teacher MOPD setup}
\label{sec:exp_setup}

The planned MOPD study uses a frozen revision of Qwen3-1.7B
\citep{qwen2025qwen3}. Four teachers start from the Qwen3 checkpoint and
receive separate post-training on mathematics, code, instruction following,
and science question answering. Teacher selection occurs before the
multi-teacher runs. The release specification requires model revisions, teacher
hashes, data splits, and the four capability scores of every teacher.

Each optimizer step samples one task, generates a task-homogeneous batch, calls
one frozen teacher, and consumes the rollout once. Every task batch targets
65,536 valid response tokens. Prompt count is estimated from earlier response
lengths, and every completed response enters the gradient. The logs record the
actual token count and overshoot.

The primary loss uses the sampled-token OPD gradient in
Appendix~\ref{app:opd_estimators}. Each response is averaged by its valid-token
count, followed by an average over responses and one shared task-gradient clip.
The trainer records the raw and AdamW-scaled scores, applies
$\lambda_i/q_i$, and calls AdamW. The target mixture is $\lambda_i=1/4$.

All methods use 600 optimizer steps, an 8,192-token response cap, temperature
1, top-$p$ 1, and disabled thinking mode. A uniform pilot fixes the learning
rate, warmup, clipping threshold, batch target, moving-average rate
$\gamma=0.95$, and probability floor $q_i\geq0.05$. Every paired seed shares a
16-step round-robin warm start, model state, AdamW state, task cursors, and
random streams.

\subsection{Mechanism audits}

\paragraph{E1: response length and task cost.}
\label{sec:exp_length_cost}
At steps 0, 150, 300, 450, and 600 of a uniform run, cached rollouts measure each
task's response length, prompt count for a fixed-token batch, token share in a
prompt-balanced mixed batch, and GPU time. Cached responses form two gradient
estimates: global token averaging and response normalization followed by a
weighted task average. E1 tests whether global token averaging follows response
length and whether response normalization keeps the explicit coefficient at
$1/4$. Timing separates rollout, teacher forward, actor forward/backward, and
optimizer work.

\paragraph{E2: corrected-gradient and cost audit.}
\label{sec:exp_estimator}
Each checkpoint supplies independent calibration and evaluation gradient banks.
The calibration bank builds each proposal. The evaluation bank measures the
distance and cosine similarity between the resampled mean gradient and the
four-task full-mixture gradient. The evaluation bank also measures the
AdamW-scaled estimator error $M(q)$ from
Equation~\ref{eq:empirical_estimator_mse} and the compute score $J(q)$ defined
in Section~\ref{sec:cost_gpas}. Each result includes its ratio to a
proposal built from held-out task gradients and costs. The preregistered
predictions are: corrected methods match the full-mixture mean, GPAS improves on
Uniform and Raw GPAS in $M(q)$, and Cost-GPAS improves on Uniform, GPAS, and
Cost-only in $J(q)$.

E2 also measures teacher--student reverse KL, the fraction of shared tokens in
the teacher and student top-16 sets, and the 95th and 99th percentiles of the
absolute token log-probability gap. The compatibility metrics show whether a large gradient
score comes with a usable teacher signal or an extreme log-ratio tail. Each
measure is reported by task and checkpoint.

\paragraph{E3: AdamW score and online tracking.}
\label{sec:exp_geometry_tracking}
For each task, one model clone applies $G_i$ and another applies a zero gradient
from the same model and AdamW state. The difference between the two parameter
vectors isolates the
task-dependent part of one AdamW step. Task-pair accuracy and Spearman
correlation compare raw gradient size and $\|\widetilde G_i\|_2$ with the measured
parameter change. The measured changes also define an exact-step oracle
proposal, which bounds the improvement available from a better optimizer
metric. A held-out teacher-loss batch records the immediate loss change from
each task gradient.

An excluded uniform pilot compares the online score moving average with fresh
gradient-bank scores every 25 steps. A parallel cost audit compares the cost
moving average with the next observed task time. The score and cost comparisons test the fixed
$\gamma=0.95$ configuration before the primary runs.

\subsection{End-to-end MOPD efficiency}
\label{sec:exp_allocation}

Every 25 steps, fresh student rollouts on a fixed prompt set measure the weighted
teacher loss
\begin{equation}
    L(N)=\sum_i\lambda_i\ell_i(N),
    \label{eq:weighted_teacher_loss}
\end{equation}
where $N$ denotes cumulative valid response tokens or measured GPU hours. The
token comparison is GPAS versus Uniform. The GPU-hour comparison is Cost-GPAS
versus Uniform and GPAS. Curves use the shortest budget completed by every
method in a comparison. An excluded Uniform pilot fixes two teacher-loss
targets before the main runs. We report the budget required to reach each target
and the area under the loss curve over the shared budget.

Each comparison reports all five paired differences, their mean, a paired
effect size, and a 95\% paired interval. An efficiency claim requires four of
five seeds in the predicted direction, an interval excluding zero, and the
matching E2 metric in the predicted direction. We separately verify that the
methods use the same number of model evaluations per step and report sampler
synchronization overhead.

The run record includes response tokens, teacher-scored tokens, prompts,
optimizer steps, GPU hours, wall-clock time, truncation, invalid outputs,
sampling probabilities, inverse sampling factors, infrastructure failures, and
every task's teacher loss.

\paragraph{Capability evaluation.}
The capability evaluation covers the initial student and checkpoints at steps
300 and 600. Metrics are MATH-500 greedy pass@1, a frozen post-cutoff
LiveCodeBench pass@1 slice, IFBench strict accuracy, and GPQA-Diamond averaged
over four samples. The capability table contains all four scores, their macro
average, and the lowest score. The full vector displays the trade-off behind
each aggregate.

\subsection{Transfer to multi-task GRPO}
\label{sec:exp_grpo}

The GRPO study uses MATH train, APPS train, and ARC-Challenge train with
executable or exact-match rewards
\citep{hendrycks2021math,hendrycks2021apps,clark2018arc}. The target is
$\lambda_i=1/3$. Each task-homogeneous batch targets 32,768 response tokens and
samples eight responses per prompt. Uniform, sequence-level Cost-Aware GRPO,
GPAS, and Cost-GPAS share a 12-step round-robin warm start and run for 400
optimizer steps. The Cost-Aware GRPO baseline first samples tasks with
$q_i=\lambda_i$, then resamples completed responses inside the selected task in
proportion to advantage magnitude divided by the square root of
prompt-plus-response length \citep{mohri2026costawarelearning}. A small uniform
mixture gives every completed response positive sampling probability.
Importance weights preserve the empirical task objective. GPAS and Cost-GPAS
select the task before generation and use the task-level correction in
Equation~\ref{eq:importance_estimator}.

The primary curves report weighted held-out KL-regularized return over tokens
and GPU hours. MATH-500, APPS test pass@1, and ARC-Challenge accuracy provide
the task vector. Multi-Task GRPO supplies a capability-oriented reference using
its published task-weight rule \citep{ramesh2026multitaskgrporeliablellm}.
