% ============================================================================
\section{Task Objective and Sampling}
\label{sec:preliminaries}
% ============================================================================

Task allocation starts with a clear definition of one task gradient. We first
average responses inside a task-homogeneous batch. We then sample one task while
preserving the user-selected mixture of task gradients.

\subsection{Define a comparable task gradient}
\label{sec:task_update}

Consider $M$ tasks. Task $i$ supplies prompts from $\mathcal D_i$ and has target
weight $\lambda_i$, with $\sum_i\lambda_i=1$. One training draw selects a task
and builds a task-homogeneous batch. For response $j$, let $L_j$ be its number
of valid response tokens and let $g_{j,t}$ be its token gradient. The task-batch
gradient is
\begin{equation}
    G_i
    =\frac{1}{n}\sum_{j=1}^{n}\frac{1}{L_j}
      \sum_{t=1}^{L_j}g_{j,t}.
    \label{eq:response_normalized_update}
\end{equation}
Each response receives equal weight inside its task. A long response supplies
more token observations and keeps the same total coefficient as a short
response. Every task batch targets a shared number of valid response tokens.
Gradient variance can still differ by task, and GPAS measures task-dependent
variance.
GPU time is recorded separately because prompt length, generation, and teacher
evaluation have task-dependent costs.

For MOPD, $g_{j,t}$ is the sampled-token policy gradient. For GRPO, $g_{j,t}$
comes from the clipped policy surrogate. Prefix sampling, token truncation,
reward clipping, and gradient clipping are part of the implemented $G_i$. The
sampler preserves the mean of the implemented $G_i$.
Appendix~\ref{app:opd_estimators} gives the OPD gradient, and
Appendix~\ref{app:grpo_update} describes the GRPO gradient. When
the trainer applies task-level clipping, $G_i$ denotes the clipped gradient from
Equation~\ref{eq:response_normalized_update}.

The mean gradient of task $i$ and the target multi-task gradient are
\begin{equation}
    h_i=\mathbb E[G_i],
    \qquad
    h=\sum_i\lambda_i h_i.
    \label{eq:target_update_field}
\end{equation}
For frozen teachers, $\lambda$ states the desired distillation mixture.

A full estimate of $h$ requires one complete batch from every task. Sampling one
task uses one rollout and one teacher or reward call per optimizer step. The
response-normalized $G_i$ provides a common unit for task sampling.

\subsection{Separate task priorities from sampling frequency}
\label{sec:update_interface}

Let $q_i$ be the probability that task $i$ supplies the next batch. After
sampling task $I$, the trainer sends
\begin{equation}
    \widehat g=\frac{\lambda_I}{q_I}G_I,
    \qquad I\sim q,
    \label{eq:importance_estimator}
\end{equation}
to the optimizer. When $q_i=\lambda_i$, the multiplier equals one. Other
sampling probabilities use the multiplier to keep the target gradient fixed.
\begin{proposition}[Conditional objective preservation]
\label{prop:conditional_preservation}
Let $\mathcal H_t$ contain the training history before step $t$, let $q_t$ be
determined by $\mathcal H_t$ with $q_{t,i}>0$, and define
$h_{t,i}=\mathbb E[G_{t,i}\mid \mathcal H_t,I_t=i]$. The corrected update
preserves the target conditional mean.
\end{proposition}
\begin{proof}
Because $q_t$ is fixed conditional on $\mathcal H_t$, averaging over the task
draw and its fresh batch gives
\begin{align}
    \mathbb E[\widehat g_t\mid\mathcal H_t]
    &=\sum_i q_{t,i}\frac{\lambda_i}{q_{t,i}}
      \mathbb E[G_{t,i}\mid\mathcal H_t,I_t=i]
      =\sum_i\lambda_i h_{t,i}.
    \label{eq:importance_unbiased}
\end{align}
\end{proof}
The weights $\lambda$ define capability priorities. The probabilities $q$
allocate task batches. Equation~\ref{eq:importance_unbiased} assigns a separate
role to each quantity. The equality concerns the gradient passed to AdamW.
AdamW's moving averages can produce different parameter paths under different
task orders.

An online sampler can use earlier gradients, measured costs, and optimizer
states to choose the next $q$. Every task keeps positive probability, and each
new task batch uses fresh rollout randomness, so
Proposition~\ref{prop:conditional_preservation} applies at every optimizer
step.

Task allocation now has a measurable objective: choose $q$ so that one
corrected task batch estimates $h$ accurately at low cost.
Section~\ref{sec:theory} derives GPAS from gradient scale and Cost-GPAS from
gradient scale plus GPU time. Experiment E1 tests the definition of $G_i$, E2
tests the corrected estimator, and the end-to-end MOPD experiment measures
training efficiency.
