% ============================================================================
\section{Practical Training Recipe}
\label{sec:training_guide}
% ============================================================================

The recipe uses one complete task batch and one optimizer step per rollout. Task
selection occurs before generation, so each step calls one teacher or reward
function.

\paragraph{1. Fix the task target.}
Choose $\lambda$ from the intended capability priorities and record it before
choosing a sampler. For frozen MOPD teachers, $\lambda$ is the teacher mixture.

\paragraph{2. Define one task gradient.}
Use a task-homogeneous batch. Average token gradients inside each response and
then average responses to form $G_i$. Apply one shared task-gradient clip. Set a
shared valid-token target, and record prompt count, token count, and GPU time.

\paragraph{3. Initialize the sampler.}
Run a short round-robin warm start. Store a moving average of
$\|\widetilde G_i\|_2^2$ for every task, where $\widetilde G_i$ uses AdamW's
stored second moment before the sampling correction. Cost-GPAS also stores a
moving average of task time. The four-task protocol uses 16 warm-start steps and
$\gamma=0.95$.

\paragraph{4. Sample and optimize.}
GPAS sets $q_i\propto\lambda_i\widehat s_i$. Cost-GPAS sets
$q_i\propto\lambda_i\widehat s_i/\sqrt{\widehat c_i}$. Apply the probability
floor, sample one task, compute and clip $G_i$, record its score, multiply by
$\lambda_I/q_I$, and call AdamW. The four-task protocol uses
$q_{\min}=0.05$.

\paragraph{5. Save and audit.}
Checkpoint the score average, cost average, timestamps, proposal, task cursors,
and random state. Log $I$, $q_I$, $\lambda_I/q_I$, valid tokens, prompt count,
GPU time, and raw and AdamW-scaled gradient norms. A large inverse sampling
factor or a stale task score triggers inspection of the probability floor.
