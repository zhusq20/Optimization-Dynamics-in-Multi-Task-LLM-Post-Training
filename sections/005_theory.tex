\section{Optimizer-Aware Task Allocation}
\label{sec:theory}
% ============================================================================

Once the second-moment target is independent of the proposal, task allocation
can be compared in one fixed AdamW geometry. Let $\bar v$ be the
bias-corrected second moment before the task draw. We define the
preconditioned gradient scale of task $i$ as
\begin{equation}
    s_i^2=\mathbb E\left\|
    \frac{G_i}{\sqrt{\bar v}+\epsilon}
    \right\|_2^2.
    \label{eq:optimizer_metric}
\end{equation}
This is the squared gradient norm after AdamW's coordinate scaling and before
the importance multiplier.

For one corrected task draw, the proposal-dependent part of the scaled
gradient's second moment is
\begin{equation}
    V(q)=\sum_i\frac{\lambda_i^2s_i^2}{q_i}.
    \label{eq:optimizer_metric_mse}
\end{equation}
Its minimum occurs at
\begin{equation}
    q_i^{\mathrm{GPAS}}
    =\frac{\lambda_i s_i}{\sum_j\lambda_j s_j}.
    \label{eq:gpas_proposal}
\end{equation}
We call this rule Gradient-Preconditioned Adaptive Sampling (GPAS). Under the
identity scale it reduces to gradient-norm importance sampling. The derivation
and its centered-error form appear in Appendix~\ref{app:gpas_proof}.

This local quantity connects directly to optimization progress. For a smooth
loss and a fixed diagonal preconditioner, the usual one-step descent bound
contains $V(q)$ as its only proposal-dependent term. The bound uses the
uncentered second moment, which explains the definition in
Equation~\ref{eq:optimizer_metric_mse}. Frozen-gradient replay tests whether
the proposal ranking from $V(q)$ predicts short-horizon teacher-loss decrease.

Task time changes the useful allocation. Let $c_i$ be the measured duration of
a task-$i$ step. The expected time per draw is $\sum_iq_ic_i$, so a GPU budget
$B$ permits about $B/(\sum_iq_ic_i)$ steps. Substituting this count into the
standard stochastic-rate bound leaves the proposal-dependent product
\begin{equation}
    J(q)=\left(\sum_iq_ic_i\right)V(q).
    \label{eq:cost_objective}
\end{equation}
Minimizing this compute-efficiency proxy gives
\begin{equation}
    q_i^{\mathrm{Cost\text{-}GPAS}}
    \propto\frac{\lambda_i s_i}{\sqrt{c_i}}.
    \label{eq:cost_gpas_proposal}
\end{equation}
This is cost-constrained Neyman allocation with tasks as strata
\citep{neyman1934representative,cochran1977sampling,mohri2026costawarelearning}.
Appendix~\ref{app:cost_connection} states the smoothness argument and the
closed-form calculation. GPU-hour curves test the proxy against end-to-end
training.

The scale contains a mean-update term and within-task gradient noise. A large
token batch may make the mean term dominant, in which case GPAS spends more
steps on tasks that currently move the student farther in AdamW coordinates.
Correlated tokens and variable response counts can keep the noise term large.
Our gradient-bank experiment estimates both terms with microbatch resampling
instead of assuming either regime.

\paragraph{Online estimates and exploration.}
After a task-$i$ step, GPAS updates a moving average of the observed squared
scale,
\begin{equation}
    \widehat s_i^2\leftarrow
    \gamma\widehat s_i^2+(1-\gamma)
    \left\|\frac{G_i}{\sqrt{\bar v}+\epsilon}\right\|_2^2.
    \label{eq:gpas_score_ema}
\end{equation}
Cost-GPAS maintains the same type of average for step time. Because only the
selected task receives a fresh observation, stale low estimates can reinforce
low sampling probabilities. A round-robin warm start and an explicit floor
provide exploration. If $p$ is the raw GPAS proposal, we use
\begin{equation}
    q_i=(1-Mq_{\min})p_i+q_{\min},
    \qquad 0<q_{\min}<1/M.
    \label{eq:proposal_floor}
\end{equation}
This rule gives $q_i\geq q_{\min}$ and
$w_i\leq \max_i\lambda_i/q_{\min}$. For four uniform objective weights and
$q_{\min}=0.05$, the largest possible multiplier is $5$. The experiments sweep
the floor and report scale age, multiplier distributions, update norms, and
clip rates.

Run a round-robin warm start to initialize one scale estimate and one optional
time estimate per task. At each step: (1) form the raw proposal from
Equation~\ref{eq:gpas_proposal} or \ref{eq:cost_gpas_proposal}; (2) apply
Equation~\ref{eq:proposal_floor} and draw one task; (3) run rollout, teacher
evaluation, and backpropagation for that task; (4) compute $w=\lambda_I/q_I$
and take a moment-consistent AdamW step; (5) update the selected task's scale
and time averages. Save these averages with the optimizer state.

Drawing several independent tasks in one step gives the same proposal for each
draw; their corrected gradients are averaged before the optimizer update.
